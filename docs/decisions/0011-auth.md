# 0011. Auth: RS256 JWTs signed by the ingest service, verified everywhere with a public key

**Status:** Accepted (contracts and schema v0.2)

## Context
Several services must trust the same user identity and tenant.

## Decision
The ingest (Django) service issues JWTs signed with a private key. All other services verify them with the public key only. Claims: sub, tenant_id, roles (viewer, reviewer, approver, admin), iss, exp. Only approver or admin may post decisions. For development, scripts/gen_dev_keys.sh and scripts/dev_token.py create keys and tokens (never commit keys).

## Why
With asymmetric keys, a compromised downstream service cannot forge tokens, unlike a shared secret.

## Trade-offs
Key distribution and rotation need care. Keycloak is a stretch goal that would replace the issuer without changing verification.

## Interview talking point
Why asymmetric JWT signing across services?

## Revisit when
We adopt Keycloak (verifiers keep working if they read its public keys).
