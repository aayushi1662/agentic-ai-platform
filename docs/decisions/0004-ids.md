# 0004. IDs: server-generated UUIDs, time-ordered when possible

**Status:** Accepted (contracts and schema v0.2)

## Context
We need IDs that are safe to expose, unique across services, and friendly to indexes.

## Decision
UUIDs are generated in application code by the server (contracts.common.new_id), using UUIDv7 when the Python version or the uuid_utils package provides it, otherwise v4. The database default gen_random_uuid() is only a safety net. Clients never choose IDs.

## Why
UUIDs avoid guessable IDs and merge cleanly across services. Time-ordered UUIDs keep index inserts local and sort by creation time.

## Trade-offs
UUIDs are bigger than integers. UUIDv7 support depends on your Python version, so the helper falls back safely.

## Interview talking point
Why not auto-increment integers? Answer: guessability, cross-service uniqueness, and index locality of v7.

## Revisit when
A newer Python or Postgres makes native UUIDv7 universal.
